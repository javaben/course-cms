# CMS — course management system

A full-stack CMS for managing courses, partners, and promotional content, with a Traditional
Chinese admin UI. It's the reference build for a hands-on course on developing with Claude Code:
every line here was generated by Claude, table by table, from a SQL schema and a set of written
conventions.

**Stack:** ASP.NET Core 9 with Dapper (no Entity Framework) · Angular 20 + PrimeNG · SQL Server

## Getting started

New here? **[docs/tutorial-getting-started.md](docs/tutorial-getting-started.md)** takes you from
clone to logged in.

Read it rather than improvising: the `database/*.sql` files create tables but insert no rows, and
there's no sign-up page, so a fresh clone has nothing you can log in as until you seed a user by
hand. The tutorial covers that step. The short version, once you have .NET 9, Node 20+, and SQL
Server Express on `.\SQLEXPRESS`:

```powershell
sqlcmd -S .\SQLEXPRESS -E -Q "CREATE DATABASE CMS;"
sqlcmd -S .\SQLEXPRESS -d CMS -E -i database/auth.sql   # then admin, course, promotion
# ...seed SysConfig['appConfig'] + your first user — see the tutorial...
dotnet run --project src/CMS.API                        # http://localhost:5000 (+ /swagger)
cd src/CMS.NG; npm install; npm start                   # http://localhost:4200
```

## Layout

```
database/   Schema DDL — four .sql files, run auth.sql first
docs/       Human documentation (see the table above)
spec/       Table specs + code-gen conventions; the input Claude generates from
src/
  CMS.API/       ASP.NET Core 9. Controllers → Repositories → IDbConnectionFactory. Dapper only.
  CMS.API.Tests/ xUnit. Controllers against in-memory fake repositories, so no database needed.
  CMS.NG/        Angular 20 standalone components + PrimeNG.
```

Each table follows the same shape end to end: a controller, an `I{Table}Repository` where all the
SQL lives, and a frontend triad of `{table}-list` / `{table}-detail` / `{table}-form`. Read
[architecture.md](docs/architecture.md) before adding one.

## Notes on running this for real

This is course material, not a hardened deployment. Two things to know before it faces anyone:

- **Secrets live in the database**, in `SysConfig['appConfig']` — the JWT signing key and the
  default password for new accounts. They're read at runtime, which is why none ship in this repo
  and why you supply your own during setup.
- **Accounts start on a shared default password** and there's no rate limiting or lockout on login.
  Fine for a lab on a laptop. Not fine on a network you don't control.
