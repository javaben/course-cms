# Design: Save Course Detail as a Shareable PDF Flyer

Generated by /office-hours on 2026-07-16
Branch: worktree-feature-course-pdf
Repo: javaben/course-cms
Status: APPROVED
Mode: Builder

## Problem Statement

A user viewing a course on the CMS detail page (`course-detail`) has no way to take that
course "off the screen." They want to export the course as a **PDF flyer** — a polished,
shareable one/two-pager they can print or send to a prospective student or partner. The
detail record is content-rich and bilingual (Traditional Chinese + English), and it already
carries a QR code that is a natural fit for a printed handout.

Goal context: **learning / leveling up full-stack.** The builder chose the server-side path
deliberately to train server-side rendering, file-response streaming, and CJK font embedding
in .NET — not the fastest path, the higher-learning one.

## What Makes This Cool

The QR code was basically born for this. On screen it's a nicety; on a **printed flyer** it's
the whole point — someone sees the sheet on a noticeboard, scans, and lands on the course.
"Save as PDF" turns a database record into a physical object you can hand to a person. That's
the "whoa": a CRUD row becomes a thing you show people.

## Constraints

- Stack: ASP.NET Core 9 (Dapper only, no EF) / Angular 20 + PrimeNG / SQL Server.
- Bilingual content with heavy **Traditional Chinese (CJK)** — the default PDF base-14 fonts
  have no CJK glyphs, so text renders as blank boxes unless a TC font is shipped and embedded.
- Must reuse the existing course-by-id data path; no new SQL.
- Solo learning project on Windows; deploy simplicity matters more than pixel-parity.
- Long free-text fields (Outline 課程大綱, cert/exam notes) are `nvarchar(max)` — layout must
  handle multi-page overflow gracefully.

## Premises (agreed with builder)

1. **Curated flyer, not a 25-field dump.** Select a marketing subset: Title, OfficialTitle,
   Partner, hours / price / credits, Objective (課程目標), Target (適合對象), Outline
   (課程大綱), certification list — laid out, not raw. Note: `GetById` returns cert/job as
   **IDs** (`CertificationPkids`), not names — the detail page resolves labels client-side via
   `LookupService`. To show cert *names* on the flyer, the endpoint must resolve them against
   the existing certification lookup (a lookup read, see Premise 3), or certs are dropped from v1.
2. **Server-side, new endpoint.** `GET /api/courses/{id:int}/pdf` — reuses the same `{id:int}`
   route-param convention as the existing `GetById` action (`id` = the int `Pkid`). Returns an
   `application/pdf` download named `course-{id}.pdf`; the detail page gets a **Download PDF**
   button. This button IS the distribution. Missing/unknown id returns `404`, matching `GetById`.
3. **Reuse the existing data path.** Calls the same `CourseRepository.GetById` the detail page
   uses — **no new course query**. Cert/job *labels* resolve via the already-existing lookup
   repository (a small read, not new course SQL). The QR (today client-side) is regenerated
   server-side.
4. **CJK font embedding is in-scope and is the main risk.** Ship a TC font (Noto Sans TC) and
   embed it. Skipping this = a flyer of blank boxes. Not optional.
5. **Accepted tradeoff:** browser print-CSS would be the fastest path to a pretty flyer, but
   the builder chose server-side for the learning value — trading "fastest pretty result" for
   "more .NET learning + a stable downloadable file."

## Approaches Considered

### Approach A: QuestPDF direct  ⭐ recommended / chosen
New `GET /api/courses/{id:int}/pdf` endpoint builds the flyer with QuestPDF's fluent C# layout API,
embeds Noto Sans TC, generates the QR server-side (QRCoder), and returns a `FileStreamResult`.
- Effort: M (human ~1-2 days / CC ~20-30 min). Risk: Low-Med.
- Pros: pure C#, one language, no browser runtime, easiest deploy; trains font embedding +
  file streaming + server QR directly; QuestPDF handles page breaks over long CJK text.
- Cons: layout is rebuilt in a fluent API (not HTML/CSS); pixel-matching the web page takes
  iteration.
- Reuses: `CourseRepository.GetById`, `LookupService` data, the QR value/logic, `CoursesController`.

### Approach B: HTML template → headless Chromium (ideal / pixel-parity)
Render an HTML flyer template server-side, convert with PuppeteerSharp (headless Chrome).
- Effort: L (human ~3-4 days / CC ~45-60 min). Risk: Med-High.
- Pros: reuse HTML/CSS; best-in-class CJK + web-font support; one template can feed both an
  on-screen preview and the PDF.
- Cons: ships a ~300MB Chromium binary; heavier deploy, slower cold start; more moving parts
  than this project needs now.

### Approach C: Client-side print route (lateral, smallest diff)
Dedicated `/courses/:id/print` Angular route with print CSS + `window.print()`; user picks
"Save as PDF."
- Effort: S (human ~half day / CC ~15 min). Risk: Low.
- Pros: fastest to a pretty flyer; browser handles CJK web fonts for free; zero new server code.
- Cons: contradicts the server-side learning goal (teaches CSS, not .NET); produces no
  server-side file, so it can't later be emailed / batched / automated.

## Recommended Approach

**Approach A (QuestPDF direct).** Lowest-risk of the server paths, keeps the codebase in one
language, and trains the exact skills the builder is here for: CJK font embedding, streaming a
file response, and server-side QR generation. B is the move only if pixel-parity with the web
page ever outweighs deploy simplicity; C is faster but is the CSS path the builder deliberately
passed on.

## Decisions (recommended answers — confirm or override)

- **Page count:** allow flow to a second page (QuestPDF paginates cleanly). Do not hard-cap or
  truncate the Outline.
- **Empty fields:** a null/empty curated field **hides its whole section** — no empty headers,
  no "N/A" placeholders. `Objective`, `Target`, `Outline`, `TowardCertOrExam` are all nullable.
- **QR target (revised in eng review):** the server QR encodes the **exact same** string as the
  existing on-page QR (`course-qr-code.ts:27`): `https://{base}/Course/Show/{pkid}/{courseId}`,
  with `{base}` (`www.uuu.com.tw`) in `appsettings`. NOT `{base}/{FriendlyUrl}` — `FriendlyUrl`
  defaults to `""` (`Course.cs:16`), which would produce a dead `{base}/` QR on a printed sheet,
  and it would not match the on-page QR. `pkid`/`courseId` are always populated.
- **Branding:** neutral clean layout for v1 (no logo / brand system yet). Deferred, not cut.
- **Auth:** the endpoint inherits the app's global JWT authorization automatically — the fix is
  simply to **not** add `[AllowAnonymous]`. No extra work; just don't open a hole.

## Open Questions

- Does a reachable public site + `PublicSiteBaseUrl` value actually exist yet? If not, v1 QR can
  fall back to encoding the CMS detail route until the public URL is live.
- **Font licensing:** Noto Sans TC is SIL OFL (safe to embed and redistribute) — confirm no
  corporate font-policy overrides this.

## Success Criteria

- Clicking **Download PDF** on a course detail page downloads `course-{id}.pdf` (id = `Pkid`).
- All Traditional Chinese text renders as real glyphs, not boxes, on a machine that does NOT
  have the TC font installed (proves the font is embedded, not just referenced).
- The flyer shows the curated field set and a scannable QR code (verified by an actual phone scan).
- A course with a very long Outline flows cleanly onto a second page (no crash, no clipped text).
- A course with null Objective/Target/Outline omits those sections entirely (no empty headers).
- An unknown course id returns `404`, not a broken/empty PDF.
- The endpoint returns `Content-Type: application/pdf` and honors existing JWT auth.

## Distribution Plan

Existing deployment pipeline covers this — the PDF is served by the existing ASP.NET Core API
as a new endpoint, and reached by the existing Angular SPA via a Download button. No new binary,
package, registry, or CI step. The only new runtime dependencies are NuGet packages (QuestPDF,
QRCoder) and one embedded font asset shipped with the API.

## Next Steps (concrete build order)

1. **Prove the font first (de-risk the hard part).** Add QuestPDF; set
   `QuestPDF.Settings.License = LicenseType.Community;` at startup (QuestPDF throws on first
   generation without it). Ship `NotoSansTC-*.ttf` as an `EmbeddedResource` (or copied to output)
   and register it once at startup via `FontManager.RegisterFont(stream)`, then reference it with
   `TextStyle.FontFamily("Noto Sans TC")`. Generate a throwaway one-line PDF containing 課程 to
   confirm glyphs render **with the font uninstalled from the OS**. Everything else is easy; this
   is the trap. (Note: QuestPDF embeds the whole face — Noto Sans TC is several MB, so PDFs run
   a few MB. Acceptable here.)
2. **Endpoint skeleton.** Add `GET /api/courses/{id:int}/pdf` to `CoursesController`, wired to
   `CourseRepository.GetById` (return `404` when null), returning a `FileStreamResult`
   (`application/pdf`, filename `course-{id}.pdf`) with a stub PDF. Confirm the endpoint
   inherits global JWT auth and downloads end-to-end.
3. **Server-side QR.** Add QRCoder; build the target string `{PublicSiteBaseUrl}/{FriendlyUrl}`,
   render it with **`PngByteQRCode`** (avoid `System.Drawing.Common` — it's Windows-only and
   breaks cross-platform), and embed the PNG bytes in the PDF.
4. **Flyer layout.** Build the curated QuestPDF layout — header (title + partner), meta row
   (hours / price / credits), body sections (objective / target / outline), cert list, QR footer.
   Hide any section whose source field is null/empty. Let long Outline paginate to page 2.
5. **Frontend button.** Add a Download PDF button to `course-detail` that hits the endpoint and
   triggers the download.
6. **Verify against Success Criteria** — including the font-uninstalled check and a real phone scan.

# Engineering Review Decisions (locked 2026-07-16)

Nine decisions from `/plan-eng-review`. These override the original body where they conflict.

### Architecture
1. **Download is a blob fetch, not a link (P1).** The frontend must call the endpoint through
   Angular `HttpClient` with `responseType:'blob'` so `auth.interceptor.ts:20` attaches the JWT
   bearer header. A plain `<a href>` / `window.open` sends no header → `Program.cs:82` FallbackPolicy
   returns 401. Component makes a temporary object URL, clicks a hidden anchor to save
   `course-{id}.pdf`, then revokes the URL. (The server `Content-Disposition` filename is decorative
   under this approach — the frontend owns the filename.)
2. **QR matches the existing on-page QR** — see revised QR-target decision above.
3. **PDF logic lives in a new `ICoursePdfService` (P2).** Controller action stays ~3 lines
   (load course → 404 or call service → `File(bytes, "application/pdf", ...)`). The service takes a
   `Course` + resolved cert labels and returns `byte[]`, so layout is unit-testable without HTTP.

### Licensing & runtime (from outside voice — both P1)
4. **QuestPDF Community-license eligibility is a BLOCKING pre-build task.** Community is free only
   for orgs under ~US$1M revenue (or individuals/nonprofits/FOSS). Confirm uuu.com.tw qualifies
   BEFORE writing code; if not, budget the paid license (~US$699+/dev/yr) or switch engine. Setting
   `LicenseType.Community` while ineligible is a license violation. (Separate from the Noto OFL font
   license, which is cleared.)
5. **Deploy target is Windows/IIS.** SkiaSharp (QuestPDF's renderer) works out of the box; no extra
   native assets. **Plan note pinned:** if anyone containerizes/Linux-hosts this later, they MUST add
   `SkiaSharp.NativeAssets.Linux` + `libfontconfig1` and re-run the font smoke test on Linux, or PDF
   generation crashes with a native-load error.

### Formatting (from outside voice)
6. **Money/number formatting is explicit.** `ListPrice`/`LearningCredit` are `decimal`; format them
   deliberately (e.g. `ListPrice.ToString("#,##0")` with an `NT$` prefix) — no raw `.ToString()`
   trailing-zero noise (`12000.00`, `3.5000`). Do NOT introduce a `zh-TW` CultureInfo (ROC/Minguo era
   date trap); the curated set has no dates, keep it that way on purpose.
7. **Cert label shape confirmed:** `GetCertificationsAsync` labels are `"Partner.Name - Title"`
   (`ILookupRepository:28`), e.g. "Microsoft - AZ-900". Accept as-is for v1; revisit only if the
   flyer wants a cleaner cert display.

### Tests
8. **CJK correctness = automated proxy + manual gate.** Unit test asserts `Build()` on CJK-heavy text
   returns valid `%PDF` bytes above a size floor and that the registered font embedded. PLUS a
   **mandatory manual gate before merge:** open a generated PDF on a machine with Noto Sans TC
   uninstalled and confirm real glyphs, not □□□.
9. **DRY drift accepted, no TODO** (user call): the public-URL formula, cert-name resolution, and
   curated field set now exist in both Angular and C#. Values are stable; accepted for an internal
   tool.

## What already exists (reused, not rebuilt)
- `CourseRepository.GetByIdAsync` — full course record, reused as-is. No new course SQL.
- `ILookupRepository.GetCertificationsAsync` — resolves cert names server-side (loads the full cert
  lookup, filters in memory by the course's `CertificationPkids`). Reused; closes the cert-name gap.
- Global auth `FallbackPolicy` (`Program.cs:82`) — endpoint inherits `RequireAuthenticatedUser`.
- Test harnesses: `InMemoryCourseRepository` + `InMemoryLookupRepository` fakes (unit style),
  `WebApplicationFactory<Program>` + login→bearer (E2E style, `AuthorizationTests.cs`).
- Existing QR value/format (`course-qr-code.ts`) — the canonical URL the server QR must match.

## NOT in scope (explicitly deferred)
- **Internal-record / full-field PDF** — this feature is the flyer only.
- **HTML→Chromium (Approach B) and client print (Approach C)** — rejected in design.
- **Batch/email/scheduled PDF delivery** — the download button is the only distribution.
- **Unifying FE/BE course-URL + cert-label + field-set** (DRY) — user chose not to track (decision 9).
- **Linux/container hosting support** — Windows-only for now (decision 5).
- **Branding/logo/design system** — neutral layout for v1.

## Failure modes (new codepaths)
| Failure | Test? | Error handling? | User sees |
|---|---|---|---|
| Missing course id | Yes — 404 unit + E2E | 404 | Clean not-found |
| No/invalid JWT on download | Yes — E2E 401 | 401 via FallbackPolicy | Error toast (frontend) |
| Font not embedded → □□□ | Proxy unit + **manual gate** | n/a (visual) | **CRITICAL if gate skipped** — silent bad flyer |
| QuestPDF license ineligible | Pre-build check (decision 4) | throws at generation if unset | 500 — caught pre-build |
| Null Objective/Target/Outline | Yes — unit (no-throw, section hidden) | hide section | Clean flyer |
| Very long Outline | Yes — unit (multi-page, no clip) | QuestPDF paginates | Multi-page PDF |
| Server 500 during generation | Yes — frontend error path | try/catch → toast | Error toast, button re-enabled |

**Critical gap flagged:** the font-render failure is SILENT (a valid PDF full of boxes) if the manual
gate is skipped. Decision 8's manual gate is the only thing catching it — it is mandatory, not optional.
