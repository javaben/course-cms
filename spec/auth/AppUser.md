# Build Spec for AppUser
- database schema: `.\database\auth.sql`
- menu group: 系統管理 Admin
- generated by `/crud` — grounded to the **actual** scaffold. `AppUser` is the near-mirror of the
  `AppRole` reference implementation: **string PK + display-only `pkid` IDENTITY + n-n via
  `AppUserRole`**. It differs only in the `PasswordHash` handling (backend-only, hashed from
  `SysConfig`) and a `PasswordUpdatedTime` audit column.

## Summary

`AppUser` (使用者) is a back-office login account. Its clustered primary key is the **string**
`UserId`; `pkid` is a display-only IDENTITY (主代碼), exactly as in `AppRole`. Each user is assigned
many roles through the `AppUserRole` junction (n-n → `AppRole`). `PasswordHash` is **never exposed to
the frontend**: it is set server-side on create from a default password stored in `SysConfig`, and
only changed via a dedicated reset-password endpoint.

| Item | Detail |
|------|--------|
| Primary Key | **`UserId` nvarchar(200)** (string PK). `pkid` int IDENTITY is display-only (主代碼). |
| Foreign Keys | None on AppUser itself |
| Required Fields | `UserId`, `UserName`, `IsActive` (bit, DB default 1). `PasswordHash` is required in DB but set server-side. |
| N-N Relationships | `AppUserRole` (AppUser ↔ AppRole) — mirror of the AppRole picker |
| Primary-Foreign Links | `AppUserRole` references `AppUser.UserId` — managed inline via n-n, no separate child list |
| Query Filters | keyword (UserId, UserName); IsActive (tri-state) |
| Default Sort | `IsActive DESC, UserId ASC` |

**Special — `PasswordHash` (per `/crud` rules):**
- Excluded from `AppUserRequest` and **all** Angular models — no form field, no API input, never returned.
- **CREATE**: read `SysConfig.configValue WHERE configKey='appConfig'` (a JSON object), extract
  `defaultPassword`, SHA-256 hash it, store as `PasswordHash`; set `PasswordUpdatedTime = UtcNow`.
- **UPDATE**: `PasswordHash` / `PasswordUpdatedTime` left untouched.
- **Reset**: a separate `POST /api/app-users/{id}/reset-password` re-hashes the default password and
  bumps `PasswordUpdatedTime`. This is the *only* update path that touches `PasswordHash`.

`pkid` is `int` IDENTITY — display-only (主代碼), never entered; not the key.

## Primary-Foreign Links

`AppUserRole` references `AppUser.UserId`. It is a **pure junction** (only `UserId` + `RoleId` beyond
its own `pkid`), so it is managed inline via the N-N Relationships section — **no** separate child
list page or inbound link button (mirrors how `AppRole` treats the same table).

---

## N-N Relationships

### AppUserRole — AppUser ↔ AppRole

Junction `AppUserRole (pkid int IDENTITY, UserId nvarchar(200), RoleId nvarchar(200))`, PK
`(UserId, RoleId)`. This is the same table the `AppRole` feature already syncs — from the AppUser side
we sync by `UserId`.

- **Related entity**: `AppRole (RoleId string PK, RoleName, PermissionLevel, Description)`.
- **New lookup** `GET /api/lookups/app-roles` → `{ roleId, roleName, label }[]` where
  `label = RoleName + ' (' + RoleId + ')'`, ordered `PermissionLevel ASC, RoleId ASC` (mirrors
  `AppUserLookup.Label` and the AppRole default sort).
- **Form (edit + new)**: `p-multiselect` of roles (`[maxSelectedLabels]="9999"`, `[filter]="true"`).
- **Detail**: read-only list of assigned role labels; list page shows a 角色數 count (correlated
  subquery, mirroring AppRole's 使用者數 `UserCount`).
- **Request field**: `RoleIds : List<string>`.
- **Read on GET-by-id**: `SELECT RoleId FROM AppUserRole WHERE UserId=@UserId ORDER BY RoleId`.
- **Sync (create + update)**: `DELETE FROM AppUserRole WHERE UserId=@UserId;` then bulk INSERT each
  `(@UserId, @RoleId)` — inside the same transaction as the scalar write (the AppRole `SyncUsersAsync`
  pattern, transposed).

## Query Filters

`POST /api/app-users/query` accepts (`AppUserQuery`):

- **keyword**: string — LIKE across `UserId`, `UserName`. (`PasswordHash` excluded — never queried.)
- **isActive**: `bool?` — tri-state exact match on `IsActive` (null = no filter, true = 啟用, false = 停用).

## API Endpoints

| Method | Route | Notes |
|--------|-------|-------|
| `GET` | `/api/app-users` | List all (ORDER BY IsActive DESC, UserId ASC) — with 角色數 count |
| `POST` | `/api/app-users/query` | Filtered query (body: `AppUserQuery`) |
| `GET` | `/api/app-users/{id}` | Get by UserId (string PK, **no `:int`**) — includes `RoleIds` |
| `POST` | `/api/app-users` | Create — **409** if UserId exists; hashes default password server-side |
| `PUT` | `/api/app-users` | Update (UserId from body) — **404** if not found; does NOT touch PasswordHash |
| `DELETE` | `/api/app-users/{id}` | Delete — **404** if not found (deletes AppUserRole rows first) |
| `POST` | `/api/app-users/{id}/reset-password` | Reset PasswordHash to default; bumps PasswordUpdatedTime — **204**, **404** if not found |

String PK → route `{id}` with **no `:int` constraint** (like `AppRolesController`). No auth attributes.

## Backend Notes

### Models

```csharp
// AppUser.cs — response model (NO PasswordHash — never returned to client)
public class AppUser
{
    public int Pkid { get; set; }                        // 主代碼 (IDENTITY, display only)
    public string UserId { get; set; } = "";             // 使用者代碼 (primary key)
    public string UserName { get; set; } = "";           // 使用者名稱
    public bool IsActive { get; set; } = true;           // 啟用 (DB default 1)
    public DateTime? PasswordUpdatedTime { get; set; }   // 密碼更新時間 (read-only)
    public int RoleCount { get; set; }                   // 角色數 (n-n correlated subquery)
    public List<string> RoleIds { get; set; } = [];      // populated on GET by id
}

// AppUserRequest.cs — write DTO (NO PasswordHash, NO PasswordUpdatedTime)
public class AppUserRequest
{
    [Required, MaxLength(200)] public string UserId { get; set; } = "";   // PK, immutable on edit
    [Required, MaxLength(200)] public string UserName { get; set; } = "";
    public bool IsActive { get; set; } = true;
    public List<string> RoleIds { get; set; } = [];                        // n-n via AppUserRole
}

// AppUserQuery.cs — search DTO
public class AppUserQuery
{
    public string? Keyword { get; set; }   // LIKE UserId, UserName
    public bool? IsActive { get; set; }    // tri-state
}
```

`AppRoleLookup` (new): `{ string RoleId; string RoleName; string Label => $"{RoleName} ({RoleId})"; }`.

### SQL — SELECT (list / query / get-by-id)

`PasswordHash` **omitted** from every SELECT. No `nchar` → no RTRIM.

```sql
SELECT u.pkid                AS Pkid,
       u.UserId              AS UserId,
       u.UserName            AS UserName,
       u.IsActive            AS IsActive,
       u.PasswordUpdatedTime AS PasswordUpdatedTime,
       (SELECT COUNT(*) FROM AppUserRole ur WHERE ur.UserId = u.UserId) AS RoleCount
FROM AppUser u
```

- `GetAllAsync` / `QueryAsync`: `ORDER BY u.IsActive DESC, u.UserId ASC`.
- `QueryAsync` keyword: `(u.UserId LIKE @Keyword OR u.UserName LIKE @Keyword)`; isActive:
  `u.IsActive = @IsActive`.
- `GetByIdAsync`: `WHERE u.UserId = @UserId`; then `SELECT RoleId FROM AppUserRole WHERE UserId=@UserId
  ORDER BY RoleId` on the same connection → `RoleIds`.

### SQL — INSERT (pkid excluded IDENTITY; PasswordHash set server-side)

```sql
INSERT INTO AppUser (UserId, UserName, IsActive, PasswordHash, PasswordUpdatedTime)
VALUES (@UserId, @UserName, @IsActive, @PasswordHash, @PasswordUpdatedTime);
```

- `@PasswordHash` = `Sha256Hex(defaultPassword)` where `defaultPassword` comes from
  `SysConfig.configValue['appConfig'].defaultPassword` (see below).
- `@PasswordUpdatedTime` = `DateTime.UtcNow`.
- No `SCOPE_IDENTITY()` needed for navigation — the PK is the string `UserId` (client already has it);
  return `GetByIdAsync(request.UserId)`. `pkid` is display-only.
- 409: `ExistsAsync(UserId)` before insert (mirrors AppRole).

### SQL — UPDATE (UserId immutable; PasswordHash NOT touched)

```sql
UPDATE AppUser
   SET UserName = @UserName,
       IsActive = @IsActive
 WHERE UserId = @UserId;
```

`affected == 0` → 404. Then delete-then-reinsert `AppUserRole` in the same transaction.

### Reset-password

```sql
UPDATE AppUser
   SET PasswordHash = @PasswordHash, PasswordUpdatedTime = @Now
 WHERE UserId = @UserId;
```

`@PasswordHash` recomputed from the `SysConfig` default; `@Now = UtcNow`. `affected == 0` → 404.

### Default-password read + hashing

```csharp
// 1. read config JSON
var json = await conn.ExecuteScalarAsync<string>(
    "SELECT configValue FROM SysConfig WHERE configKey = 'appConfig'");
// 2. extract defaultPassword (System.Text.Json)
using var doc = JsonDocument.Parse(json);
var defaultPassword = doc.RootElement.GetProperty("defaultPassword").GetString()!;
// 3. SHA-256 → lowercase hex (64 chars, fits nvarchar(800))
var hash = Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(defaultPassword))).ToLowerInvariant();
```

- **Decision**: store SHA-256 as **lowercase hex**. Documented so the login side can match.
- If `SysConfig['appConfig']` is missing or has no `defaultPassword`, throw a clear
  `InvalidOperationException` ("appConfig.defaultPassword 未設定") → surfaced as 500 (misconfiguration).
- A small `IPasswordDefaultProvider` / private helper on the repo encapsulates read+hash so both
  CREATE and reset-password share it.

### DELETE

Delete `AppUserRole` rows first (FK), then the `AppUser` (mirrors AppRole `DeleteAsync`).

### Special Column Notes

- `UserId` string PK → route `{id}` (no `:int`), 409 on create, immutable on update, body-carried PUT.
- `pkid` int IDENTITY → **display only**, excluded from INSERT/UPDATE, not the key.
- `PasswordHash` → excluded from all SELECTs and the Request; only written by CREATE + reset-password.
- `PasswordUpdatedTime` → `datetime` NULL; Dapper returns `Kind=Unspecified`; frontend appends `'Z'`
  for display (we store UTC).

### Service

- Standard `list` / `query` / `getById` / `create` / `update` / `delete`.
- `resetPassword(userId: string)` → `POST /api/app-users/{encoded}/reset-password`, returns `void`.

### List component

- Columns: 主代碼 (pkid), 使用者代碼 (userId), 使用者名稱 (userName), 啟用 (isActive → `p-tag` 是/否),
  角色數 (roleCount), 密碼更新時間 (passwordUpdatedTime → `{{ v + 'Z' | date:'yyyy-MM-dd HH:mm' }}`), 操作.
- Filter drawer: keyword `pInputText`; IsActive tri-state `p-select` (全部 / 啟用 / 停用, `appendTo="body"`).
- Default sort `isActive DESC` then `userId ASC`. Session keys: `app-user-list-filters` / `-sort` / `-page`.
- Delete confirm: `確定要刪除主代碼 <b>${item.pkid}</b>「${item.userId}」？`

### Detail component

- Show pkid / userId / userName / isActive / passwordUpdatedTime and the assigned role labels
  (match `roleIds` against the app-roles lookup).
- Toolbar `重設密碼` button → confirm dialog → `resetPassword(userId)` → success toast
  (`密碼已重設為預設密碼`) → reload.
- **No password display** — only the update time.

### Form component

- Reactive Forms; `forkJoin` loads the app-roles lookup (+ the user on edit), then `patchValue`.
- `userId` — `pInputText`, required, `.disable()`d in **edit** mode (string PK immutable; shown
  read-only), enabled in new mode. Header shows pkid read-only in edit mode.
- `userName` — `pInputText`, required.
- `isActive` — `p-toggleswitch` (default true on new).
- `roleIds` — `p-multiselect` of roles (`optionLabel="label"`, `optionValue="roleId"`,
  `[maxSelectedLabels]="9999"`, `[filter]="true"`).
- **No password field of any kind.** In edit mode, optionally show 密碼更新時間 read-only + a
  `重設密碼` button (same action as detail). New users get the default password automatically (server-side).
- Sticky `p-toolbar`.

### Sidebar placement

Existing group **系統管理 Admin** already has the `使用者 AppUser` item (route `/app-users`) — **no nav
change needed**, the new routes just make it resolve.
